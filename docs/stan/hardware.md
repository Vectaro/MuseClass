# Залізо і деплой: де живе сервер

## Ланцюжок машин (2026-09-29, доповнено 2026-09-30)
Старий мініПК відпав: заслабкий, і на ньому будуть інші задачі. Машини йдуть
послідовно, не паралельно, а код і `compose.yaml` в усіх спільні:
1. **Робочий ПК Влада, Windows 10/11 — тестовий стенд.** Перша збірка,
   `mvn verify`, ганяння API з емулятора. Цілодобова робота не вимагається.
2. **Малина — тимчасовий «прод».** Спершу тест, потім реальне користування.
3. **Нормальний мініПК — постійний дім.** Коли буде куплений.

**Можливий варіант (2026-09-30), не рішення:** NUC на Celeron J3455 за
~2000 грн, 8 ГБ RAM, SSD 256 ГБ. Поки лише знайдене оголошення. Якщо
купується — малина з плану випадає, NUC закриває пункт 3 одразу після ПК.

## Принцип заліза (2026-09-29, Влад)
Деплой розраховується на мінімальне залізо (Pi 4, 2 ГБ, microSD) так, щоб на
кращому воно працювало краще, але так само стабільно. Сильніша машина
відрізняється лише значеннями в `.env`, а не кодом чи `compose.yaml`.

## Переїзди між машинами
Через дамп: `backup.ps1` / `backup.sh` на старій, `pg_restore` на новій (команда
в коментарі скрипта). Також перенести `.env` з тим самим `JWT_SECRET`, інакше
всі видані токени стануть недійсними. Адреса Funnel прив'язана до імені машини
в tailnet (`<машина>.<tailnet>.ts.net`), тож при переїзді вона зміниться: або
міняй базову адресу в `BuildConfig` клієнта, або перейменуй машини в адмінці
Tailscale так, щоб нова отримала те саме ім'я, а стару спершу прибери.

## Робочий ПК (Windows 10/11)
- **Вимоги:** Windows 10 22H2+ або 11 23H2+, 64-біт (Home теж годиться).
  Віртуалізація в BIOS/UEFI, Docker Desktop на WSL 2, 8 ГБ RAM або більше,
  Tailscale для Windows, Git.
- **Запуск:** `.env` з `DB_PASSWORD` і `JWT_SECRET`, далі
  `docker compose up -d --build` і `tailscale funnel --bg 8080` (PowerShell від
  адміністратора).
- **Живучість:** Docker Desktop працює в сесії користувача — автостарт Docker
  при вході і вимкнений сон (`powercfg /change standby-timeout-ac 0`, те саме
  для hibernate). Після перезавантаження треба увійти в систему. Tailscale —
  служба Windows, стартує сам. Пам'ять WSL за потреби — у
  `%UserProfile%\.wslconfig`.
- **Бекап:** `backup.ps1` через Планувальник завдань. Дамп пишеться у файл
  всередині контейнера і копіюється через `docker compose cp`, бо PowerShell 5.1
  псує бінарний вивід при `>`. Файл збережено з BOM, інакше 5.1 ламає кирилицю.
- **Dev на тому ж ПК:** окрема база на порту 5433 і застосунок на 8081.

Опускати сумісність до Windows 7/8.1 не будемо: Docker Desktop там не ставиться,
Java 21 їх офіційно не підтримує, а нижче Java 17 Spring Boot 4 не йде.

## Малина
Ще не куплена. Деплой-файли — у [`server/pi/`](../../server/pi/README.md)
(2026-10-05 Влад розділив деплої за машинами): свій `compose.yaml` з
`build: ..`, `.env.example`, `backup.sh`, README з покроковою інструкцією.
Спільний код (`src`, `pom.xml`, `Dockerfile`, `dev/`) лишається в `server/`,
деплой ПК — справа чату про ПК. Команди `docker compose` — з `server/pi/`.
Годиться і для будь-якого Linux-сервера (NUC).

- мінімум — Pi 4 на 2 ГБ, microSD A2 від 32 ГБ, swap від 1 ГБ;
- оптимально — Pi 5 на 4 ГБ, SSD (USB 3 або NVMe HAT), офіційний блок живлення
  на 27 Вт, Active Cooler;
- найкраще — Pi 5 на 8 ГБ з NVMe, плюс UPS на малину і роутер. UPS дає більше,
  ніж різниця між 4 і 8 ГБ: без роутера Funnel однаково ляже.

Pi 3 з 1 ГБ не підходить. ОС тільки 64-бітна (`uname -m` → `aarch64`).

**Під мінімалку зроблено (2026-09-29):** логи Docker 10 МБ × 3 на сервіс;
Postgres `checkpoint_timeout=15min`, `wal_compression=on` (`synchronous_commit`
не чіпали — при відключеннях світла це втрата даних); Maven у збірці
`-Xmx512m`; `start-period` healthcheck 180 с; `backup.sh` з `BACKUP_DIR` на
інший носій і записом через `.part`, приклад cron з `$HOME`. У README: таблиця
заліза, Docker через get.docker.com, swap, збірка arm64-образу на ПК через
`buildx` + `docker save`/`load` як запасний варіант.

**Під монорепо (2026-10-05):** у `compose.yaml` зафіксовано `name: museclass`,
бо інакше compose бере ім'я проєкту з теки (`server/`). Том бази —
`museclass_pgdata`, образ — `museclass-api`, незалежно від того, куди клоновано
репо. На малині клонувати весь репо і працювати з `~/MuseClass/server/pi`
(так і в README, і в cron-рядку `backup.sh`). Якщо колись буде машина, де сервер уже крутився під старим ім'ям
теки, дані лежать у старому томі — переносити дампом, а не перейменуванням.

Тести на малині без JDK на хості (з `server/`, не з `server/pi/`):
`docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD":/src -w /src maven:3.9-eclipse-temurin-21 mvn -B verify`

## NUC на J3455
4 ядра Apollo Lake, x86-64 — сильніший за Pi 4 і без arm64-нюансів. Для JVM +
Postgres і десятків користувачів вистачає, якщо поруч немає важких задач.
Умови:
- від 4 ГБ RAM (офіційна стеля чипа 8 ГБ DDR3L; 16 ГБ у когось стартує, але без
  гарантії); з 4+ ГБ піднімати `-Xmx` і `shared_buffers` в `.env`;
- SSD, не eMMC і не флешка — Postgres пише постійно;
- Linux (Debian 12/13 або Ubuntu Server LTS), не Windows: Docker без WSL,
  tailscaled як служба, бекап — `backup.sh` через cron;
- не брати дистрибутиви з мінімумом x86-64-v3 (RHEL/Alma/Rocky 10): чип тягне
  лише x86-64-v2 (немає AVX);
- якщо Linux зависає намертво без логів — відомий баг C-станів Apollo Lake,
  лікується параметром ядра `intel_idle.max_cstate=1`;
- в BIOS увімкнути старт після втрати живлення (якщо є); BIOS — останній, NUC6
  більше не оновлюється.

**Під знайдений NUC (8 ГБ, SSD 256 ГБ)** апгрейди не потрібні. У `.env`: heap
API близько 768 МБ – 1 ГБ, Postgres `shared_buffers` 512 МБ і
`effective_cache_size` близько 2 ГБ. Разом сервер займе ~2 ГБ. Дампи бекапу на
тому ж SSD — не бекап від смерті диска; копію тримати ще десь.

При купівлі перевірити: BIOS без пароля, вентилятор не гуде, memtest хоча б
один прохід, SMART диска (`smartctl -a`), блок живлення 19 В у комплекті.

## Розглянуто й відкинуто (2026-09-30)
- **Raspberry Pi OS на x86 чи ТВ-приставці** — не ставиться (прив'язана до
  заліза малини). На x86 — звичайний Debian.
- **Прошита ТВ-приставка (Amlogic/Rockchip) через Armbian** — неофіційні
  збірки, ядра ламаються, характеристики брешуть; для бази з даними учнів
  ризиковано.
- **Dell Wyse 3040** (Atom x5-Z8350, 2 ГБ розпаяні, eMMC 8/16 ГБ) — рівень
  мінімалки, годиться як тимчасовий прод з SSD через USB 3, але не як постійний
  дім. «Кастомки» на 4–16 ГБ RAM — перевіряти `free -h` на місці.
