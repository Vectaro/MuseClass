# Перенесення на Android

Код — в `android/`: Java, `ua.museclass.app`, minSdk 24, target/compile 37,
AGP 9.4.1, Gradle 9.6, Material3 DayNight. Збирається JDK з Android Studio.

## Що є (2026-10-06)
Перший наскрізний шматок: вхід → «Моя бібліотека» → партитура.

- **`:musicxml`** — окремий модуль на чистій Java 8 (`--release 8`, без
  Android). Порт `fromMusicXML` з `prototype/index.html` на `XmlPullParser`,
  `.mxl` через `java.util.zip` з обмеженням 64 МБ розпакованого і 1000 файлів.
  Модель: `Score` → `Part` → `Measure` → `Note` → `Pitch` (ступінь +
  альтерація + октава, `unpitched` для ударних); фортепіанні стани — окремі
  партії; позначки такту — `Bar`.
  - Свідомо інакше, ніж у прототипі: розмір, тональність, ключ і стрій партії
    — **початкові** (прототип бере останні в файлі; див. `open.md`); такт без
    нот лишається порожнім тактом, а не випадає; альтерація ціла.
  - Еталони: `android/tools/golden.js` проганяє 9 демо прототипу (через
    `toMusicXML`) і 2 фікстури через JS-парсер і пише JSON у
    `musicxml/src/test/resources/golden/`. `GoldenTest` звіряє Java поле в
    поле — усі 11 збігаються. Перезапускати скрипт, коли міняється парсер
    або демо прототипу (потрібен `npm install` у `prototype/`).
  - Перевірено на 4 файлах з dev-сервера: кількість тактів збігається з
    `measures` сервера, бенд — 7 партій з ударними.
- **Мережа** (`app/.../api/`): OkHttp 4.12 + Gson, `ApiClient` за
  [`docs/api.md`](../api.md). Помилки `problem+json` → поле `detail` як є;
  401 без тіла на запиті з токеном стирає сесію і веде на вхід; формат Spring
  без `detail` → «Щось пішло не так.»; немає зв'язку — окремий текст.
  JWT, `expiresAt`, `userId`, ім'я — у SharedPreferences `session`,
  виключеному з резервних копій. Сесія вважається живою до `expiresAt`
  мінус хвилина. Тести — MockWebServer.
- **Екрани**: `MainActivity` (розподільник) → `LoginActivity` (вхід /
  реєстрація, ім'я підказується з пошти) → `LibraryActivity`
  (`/me/library`, тягнути вниз — оновити, «Вийти» в меню, кнопка «Вступити
  в клас») → `ScoreActivity` (картка + файл; назва, партії з
  ключем/розміром/тональністю і кількість тактів — з власного парсера; без
  рендеру).
- **Вступ у клас** — `JoinClassActivity`, `POST /classes/join`. Формат коду
  не перевіряємо самі: сервер прощає регістр, пробіли, дефіс, кириличні
  двійники, а його `detail` («Код класу має вигляд PNO-3A.», «Клас з таким
  кодом не знайдено.») показуємо як є. Успіх → назад у бібліотеку, снекбар
  «Ти в класі «…».» і перезавантаження списку.
- **Кеш файлів партитур** — `api/ScoreFiles`: `filesDir/scores/<id>.bin` +
  `<id>.etag`. Є копія — запит з `If-None-Match`, на 304 віддаємо її. Нову
  копію пишемо, лише якщо sha256 вмісту збігся з ETag (інакше просто не
  кешуємо). 403/404 стирають копію, вихід з акаунта — усі копії. Тека
  виключена з резервних копій. Офлайн поки не дає нічого: картка
  (`GET /scores/{id}`) без мережі однаково не прийде.
- **Debug і API 37**: з Android 17 з'єднання з приватними адресами
  (`10.0.2.2`, `192.168.*`) без дозволу `ACCESS_LOCAL_NETWORK` («Пристрої
  поблизу») **мовчки відкидаються** — OkHttp бачить тайм-аут. Debug-маніфест
  оголошує дозвіл, `BaseActivity.askLocalNetwork()` просить його на вході й у
  бібліотеці (тільки якщо маніфест його оголошує). Release ходить на
  публічний https і дозволу не має; **якщо колись release ходитиме на сервер
  у локальній мережі (малина/NUC за IP), дозвіл треба буде додати і в
  release.**
- Помилки фонових запитів пишуться в logcat з тегом `MuseClass`.
- Desugaring увімкнено, R8 для release тримає DTO для Gson (`rules.keep`).

## Перевірки
З `android/`: `./gradlew :musicxml:test :engraving:test :app:testDebugUnitTest assembleDebug lintDebug`
— 11 + 4 + 19 тестів, lint 0 помилок. Еталони: `node android/tools/golden.js`
(парсер) і `node android/tools/golden-render.js` (верстка) — перезапускати
після змін у парсері, `engine.js` або демо прототипу. Release з R8 збирається (перевірено з
тимчасовою адресою в `local.properties`).

**В емуляторі (2026-10-06, `Pixel_9`, API 37, userdata 6 ГБ) проти
dev-сервера**: вхід `student@dev.museclass` → бібліотека (4 партитури, «Dev:
оркестр») → кожна з 4 партитур відкривається, партії/ключі/транспозиції
збігаються з прототипом (труба in B♭ без знаків і альт-сакс 1♯ при концертних
2♭ у марші). Кеш: копії лягають на диск, сервер на збережений ETag дає 304.
Вступ у клас: неправильний формат → 400 з текстом, неіснуючий код → 404 з
текстом, `dev 6k` → успіх. Знайдено й виправлено: дозвіл на локальну мережу
(див. вище), білі іконки статус-бару на світлій темі, Enter після помилки
вступу закривав екран (вимкнене поле віддавало фокус стрілці «назад»).

## Нотатки щодо перенесення
- Парсер MusicXML — чиста логіка, лягає на `XmlPullParser` майже один в один.
- `.mxl` розпаковується через `java.util.zip` з коробки.
- Рендер — `Canvas` (шлях ключа з `clef.js` у `Path` один раз, далі матрицею).
- **Звук — SoundFont (SF2) через FluidSynth або вбудований Sonivox, а не синтез
  із гармонік.** Див. «Звук» у [`decisions.md`](decisions.md).
- Під API 24 стежити за desugaring для Java 8.
- Тема — `DayNight` з `MODE_NIGHT_FOLLOW_SYSTEM` за замовчуванням і збереженим
  вибором користувача.
- Фото — `PickVisualMedia`.
- «Тримати екран» — `FLAG_KEEP_SCREEN_ON` на вікні плеєра.
- Витягнуті партії — через `FileProvider` + `ACTION_SEND`, архів збирати
  `java.util.zip`.
- Мережа: базова адреса — `BuildConfig.API_BASE` (зроблено 2026-10-06).
  - debug: `http://10.0.2.2:8081/api` — dev-сервер на тому ж ПК, емулятор
    бачить комп на `10.0.2.2`. Http дозволено тільки в debug і тільки для
    `10.0.2.2` (`app/src/debug/res/xml/network_security_config.xml`).
  - release: адреса в репо **не вшита**. Її вписують у `android/local.properties`
    рядком `museclass.releaseApiUrl=https://.../api` (адреса Funnel, пізніше
    білий IP). Без неї або без `https://` release не збирається — падає задача
    `checkReleaseApiUrl`. Перевірено обидва випадки.

## Рендер нотного стану (2026-10-07)
Рішення — у [`decisions.md`](decisions.md): в'язки в першому кроці, перенос
за шириною, аркуш — білий «папір» в обох темах, інверсія — налаштування.
Знімки всіх партій 4 dev-партитур і перелік, що малюється, —
[`docs/android/render/`](../android/render/README.md).

- **`:engraving`** — чиста Java 8 поверх `:musicxml`. `Staff` — порт
  `measureWidth` і `renderStaff` з `prototype/engine.js` рядок у рядок:
  партія → список фігур (`Shape`: лінія, прямокутник, головка-еліпс з
  номером події, коло, контур-гліф, знак альтерації, текст) у координатах
  прототипу (проміжок 10, крок 5). Кольорів у фігурах немає — лише роль
  «чорнило / приглушене».
  - Малює тіло стану й в'язки. **Ще ні** (наступні кроки): ліги, тріолі,
    вольти, написи, динаміка/вилки, текст пісні, фермата, багатотактові паузи.
  - `Glyphs` — контури ключів, пауз, прапорців, хрестика з прототипу; знаки
    ♯ ♭ ♮ 𝄪 𝄫 — свої вектори (у прототипі це текст шрифтом).
  - `Sheet` — перенос: такти набираються, поки влазять, потім розтягуються
    на всю ширину (`stretch` множить відступи всередині такту, гліфи не
    тягнуться); короткий (< 70 %) останній рядок не тягнеться; один задовгий
    такт — стискається. Тональність на початку системи — та, що діє
    (з урахуванням зміни в першому такті системи), розмір — лише на першій.
  - Свідомо інакше за прототип: **лінії стану починаються під ключем**
    (`staffStart`), у прототипі — після ключа, і ключ висить зліва;
    **знаки альтерації після зміни тональності** рахуються від нової (у
    прототипі — від початкової). Обидва — в `open.md` для прототипу.
- **Еталони**: `android/tools/golden-render.js` верстає 9 демо справжнім
  `renderStaff` (по 3 такти на систему, тіло без шару ліг/тріолей) і пише
  канонічні списки фігур; `GoldenRenderTest` звіряє фігуру в фігуру з
  допуском 0,05 — 57 систем, 1808 фігур, усе збігається. Мутації (довжина
  штиля) тест ловить. `SheetTest`: ніщо не ширше екрана, такти без
  пропусків, рядки розтягнуті, фігури всередині системи, знаки після зміни
  ключа посеред системи.
- **Застосунок**: тап по партії в `ScoreActivity` → `PartActivity`: файл з
  кешу `ScoreFiles`, розбір, системи в `RecyclerView` (`SystemView` на
  систему), перекладка при зміні ширини. `SheetPainter` малює фігури на
  `Canvas`, контури гліфів — `Path` один раз, далі матрицею. Масштаб:
  одиниця 0,14 мм (проміжок 1,4 мм) за `xdpi`.
- **Кольори — параметри** (`SheetColors`): `sheet_paper` `#FFFFFF`, у нічній
  темі `#FAF8F3` (як `--paper` прототипу), чорнило `#1B1B1E`, номери тактів
  `#8A8A92`. Інверсія — `sheet_inverted` у SharedPreferences `settings`
  (папір `#151828`, чорнило `#E9EAF3`); перемикач з'явиться в розділі
  «вигляд» профілю.
