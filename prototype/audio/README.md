# audio/

Тембри інструментів не вигадані й не взяті семплами. З реальних записів
(FluidR3 GM) заміряні числа, і в сторінку потрапляють тільки вони — самих
семплів у репо немає.

## Модель

    amp(k, f0) = k^(-(a + b·log2(f0/261))) · F(k·f0)

**Джерело** `k^(-a)` — спад по НОМЕРУ гармоніки (щипок, удар, губи),
однаковий на всі висоти. **Резонатор** `F(f)` — корпус чи труба, привʼязаний
до ЧАСТОТИ, тому форманта не їде вгору разом з нотою. Член `b` дає залежність
від регістру: жива мідь на низьких нотах темніша зверху.

Дві попередні спроби й чому вони не звучали:

1. **Спектр за номерами гармонік.** Труба вище C5 ставала пищалкою, вокал —
   роботом. У вокалу на C3 пік на 4-й гармоніці, на C4 — на 2-й, і це ті самі
   523 Гц: форманта стоїть за частотою, а не за номером.
2. **Одна усереднена крива по частоті.** Форманту тримала, але на кожній
   окремій ноті давала високим гармонікам забагато: фортепіано звучало як
   труба з клавесином, гітара як клавесин, бас як тихий тромбон. Бракувало
   спаду по номеру.

## Порядок

    sh fetch-samples.sh      # завантажити еталонні записи (не в репо)
    python3 fit.py           # підгонка → srcfilter.json
    python3 verify3.py       # звірити синтез із семплами, малює sf_check.png
    python3 ../tools/build.py  # вставити таблицю голосів у index.html

`analyze2.py` показує, де в реального інструмента пік спектра на різних
висотах — саме цим доведено, що форманта тримається за частотою.
`analyze3.py` міряє, наскільки швидше згасають верхи проти низів (у
фортепіано — у 3.6 раза; без цього щипкові звучать як клавесин); його
результат лежить у `decays.json` і йде в поле `hr`.

Потрібні `ffmpeg`, `numpy`, `matplotlib`.

## Чому підгонка має стримувальні члени
Без них `a` і `F` не розрізняються однозначно: підгонка дає відʼємний спад,
скомпенсований кривим резонатором. Воно підходить під дані, але розвалюється
на краях діапазону. Тому `a` тягнеться до 1.0, `b` до 0, а резонатор
згладжується по другій похідній.

## Файли

| `fetch-samples.sh` | качає еталонні записи |
