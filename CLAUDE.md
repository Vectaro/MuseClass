# Правила для чатів Claude, що працюють з цим репозиторієм

Проєкт MuseClass ведеться кількома паралельними чатами (загальний, прототип,
сервер, малина/залізо, далі Android). Обмінюються вони тільки через цей
репозиторій. Влад спілкується українською, коротко і по суті.

## Головне
1. **Стан проєкту живе в `docs/stan/`**, а не в пам'яті чату. На початку роботи
   прочитай `docs/stan/README.md` і `docs/stan/open.md`, далі — файл своєї
   ділянки.
2. **`git pull --rebase` перед кожною правкою і перед кожним пушем.** Між pull і
   push не повинно бути довгої роботи над тим самим файлом стану. Конфлікт —
   розв'язати злиттям, ніколи не `push --force` і не «взяти свою версію цілком».
3. **Правиш свою ділянку.** Кожен чат пише переважно у свій файл стану і свою
   теку коду:

   | Ділянка  | Код           | Файл стану                |
   |----------|---------------|---------------------------|
   | прототип | `prototype/`  | `docs/stan/prototype.md`  |
   | сервер (код + ПК) | `server/` (спільне) і `server/pc/` | `docs/stan/server.md` |
   | залізо (малина) | `server/pi/` | `docs/stan/hardware.md` |
   | Android  | `android/`    | `docs/stan/android.md`    |
   | загальний| —             | `README.md` стану, `decisions.md` |

   `docs/stan/open.md` і `docs/stan/decisions.md` спільні: правити точково,
   одразу комітити й пушити.
4. **Відкрите — в одному місці.** Нова задача, рішення, яке чекає Влада, або
   «запропоновано, не зроблено» → `docs/stan/open.md`. Закрив — прибери звідти
   і перенеси результат у файл ділянки.
5. **Коміти маленькі й зрозумілі**, українською: `сервер: Testcontainers 2 у pom`,
   `стан: NUC куплено`. Один коміт — одна думка.
6. **Ніяких секретів у репо.** `.env`, дампи бази, ключі, токени Tailscale —
   тільки `.env.example`. `.gitignore` це тримає, але перевіряй `git status`.
7. **Прототип** живе також як артефакт
   https://claude.ai/artifact/QrwX2jX9GHz6VV9dvLL4hM — оновлювати за цим URL,
   не публікувати новий. Джерело правди — `prototype/` у репо: спершу коміт,
   потім публікація того самого файлу в артефакт.
8. **Пушиш тільки коли Влад попросив або погодив задачу.** Дрібні оновлення
   стану в межах погодженої роботи — можна без окремого питання.

## Як підключитися з нового чату
Підключи репо `Vectaro/MuseClass` з доступом на запис, клонуй, прочитай цей
файл і `docs/stan/`. Якщо в чаті є файли, яких немає в репо, — закинь їх у
свою теку окремим комітом.

## Локальна сесія на робочому ПК
Claude Code на ПК Влада (Windows) працює з клоном у `C:\MuseClass`.
- **Кожна локальна сесія — у своєму worktree**, не в спільній теці: інакше
  незакомічене одного чату блокує `pull` іншому. `C:\MuseClass` (гілка `main`)
  — сервер і загальне; Android — `C:\MuseClass-android`, гілка `android`
  (`main` уже зайнятий основною текою). Гілка `android` стежить за
  `origin/main`: `git pull --rebase` тягне main, пуш — `git push origin
  HEAD:main`. Новий worktree: `git worktree add -b <гілка> C:\MuseClass-<ділянка> main`
  і скопіювати незакомічені локальні файли (`android/local.properties`).
- **Можна без питання:** `mvnw` (`server/`), `npm test` (`prototype/`),
  dev-сервер — тільки на портах 8081 (API) і 5433 (Postgres).
- **Без слова Влада не чіпати:** бойовий compose-проєкт `museclass-pc` і том
  `museclass-pc_pgdata` — ні `up`, ні `down`, ні `rm`, ні `volume`.
- **Тільки після ОК Влада:** `tailscale`, `powercfg`, Планувальник завдань.
- `.env` не читати — заборонено в `.claude/settings.json`.
